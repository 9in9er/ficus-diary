# План восстановления локальной копии Firestore

Это инструкция для отдельной будущей операции. Скрипт восстановления не добавлен
и восстановление не запускалось. Создание копии не меняет Firestore.

## Проверить исходную копию

1. Сохраните вместе `plants.json` и `integrity.json`. Не редактируйте оригиналы.
2. Из корня репозитория выполните локальную проверку:

   ```powershell
   npm.cmd run verify:firestore-backup -- ".\backups\<точная-папка-копии>"
   ```

3. Продолжать можно только при коде `0`, корректных JSON и SHA-256 и совпавших
   `documentCount` и `sourceCount`. Проверьте `projectId`, `(default)` и `readTime`
   в manifest. Папка с `.partial` не является подтверждённой копией.

## Сначала восстановить в изолированную среду

1. Будущий инструмент должен требовать явный Project ID назначения, отдельные
   тестовые credentials или явно выбранный Emulator. Нельзя автоматически брать
   production-проект из текущего `.env.local`. Начните с локального Firestore
   Emulator с `demo-` Project ID или пустого тестового проекта.
2. Этот JSON не является форматом managed export: `gcloud firestore import`
   не подходит. Нужен отдельный восстановитель типизированных `Value`, без
   преобразования `integerValue` через JavaScript `Number` и Timestamp через `Date`.
3. Для REST-восстановителя каждое `documents[i].document.fields` уже соответствует
   схеме Firestore. Ресурс назначения строится из **явно выбранного** проекта,
   базы `(default)` и исходного `documents[i].id` в коллекции `plants`.
   В `createDocument` передают `documentId` и `{ fields: ... }`; исходные
   `name`, `createTime`, `updateTime` не отправляют как поля документа.
4. Безопасный начальный режим — **create-only**: если ID уже существует, остановить
   операцию и показать конфликт без вывода содержимого. Нельзя использовать
   `set`, upsert, merge или удаление целевой коллекции как неявное поведение.
   Запросы ограничивать по размеру: base64 может занять почти весь лимит документа.
5. Типы должны остаться типами: `timestampValue`, `geoPointValue`, `integerValue`,
   `bytesValue`, `referenceValue`, `doubleValue`, `arrayValue`, `mapValue`,
   `booleanValue`, `nullValue` и `stringValue`. Нельзя записывать wrappers
   `{"stringValue": ...}` как обычные пользовательские maps через Admin `set`.
   При использовании Admin SDK потребуется явный декодер в Timestamp, GeoPoint,
   Buffer, DocumentReference, BigInt и остальные типы с сохранением точности.
6. Ссылки `referenceValue` содержат исходный Project ID. При восстановлении
   в тестовую среду заранее задайте и проверьте политику: сохранять их как
   оригинальные ссылки либо переназначать только ссылки внутри исходного проекта.
   Все прочие поля, включая `userId`, `photoKey` и base64 `photo`, сохранять как есть.
7. После частичного сбоя ничего не удалять автоматически. Зафиксировать только
   пути успешно созданных документов, сверить их с копией и явно определить
   продолжение. Не повторять запись поверх существующих документов.

## Проверить результат до любых действий с production

- Сверьте число документов и набор ID, все типизированные поля и длину/хеш полных
  строк `photo` локально, без вывода фото или текста заметок в журнал.
- Проверьте активное растение, вишлист, корзину, заметки, историю полива и
  удобрений; отдельно вложенные Timestamp, GeoPoint и другие присутствующие типы.
- `createTime`/`updateTime` документа назначатся заново сервером. Поля документа
  с такими же именами восстанавливаются из `fields` и остаются исходными.
- Firebase Auth, Rules, индексы, подколлекции и сами S3-объекты в эту копию не
  входят. Приложению потребуется соответствующий пользователь `userId`; для
  сохранённых `photoKey` понадобятся исходные объекты. Base64-фото автономны.

Восстановление в production — отдельная явно согласованная операция после
успешной проверки изоляции и подготовки свежей резервной копии текущих данных.
Если ID заняты, заранее составьте точный план разрешения конфликтов и проверки
конкурентных изменений. Эта инструкция не даёт команды перезаписи production.

Схемы для будущего восстановителя:
[Firestore Value](https://firebase.google.com/docs/firestore/reference/rest/v1/Value),
[createDocument](https://firebase.google.com/docs/firestore/reference/rest/v1/projects.databases.documents/createDocument).
