# Адресная миграция двух оставшихся фотографий

Команда `migrate:remaining-photos` использует отдельный скрипт
`scripts/migrate-remaining-photos.cjs`. В нём зафиксированы проект
`my-plants-app-8f6fc` и только два документа:

- `mnV2BvHKuxE7XZr5mp1B`
- `yJ8a7aS3fLK0tb3dfqkM`

UID не требуется указывать: для каждого документа он читается непосредственно из Firestore.
Параметры `--user`, `--plant`, `--all`, `--limit`, списки ID и другой проект не принимаются.
Запросов ко всей коллекции или ко всем растениям владельца нет: выполняются только чтения
по двум фиксированным путям `plants/<id>`.

## Dry-run в PowerShell

Из корня проекта, с Node.js 24 и существующими настройками `.env.local`:

```powershell
npm.cmd run migrate:remaining-photos -- --project my-plants-app-8f6fc --dry-run
$LASTEXITCODE
```

Это режим по умолчанию. Он читает ровно два документа, определяет владельцев,
проверяет условия и конвертирует фотографии в WebP только в памяти.
Нет S3-запросов, загрузок, транзакций записи, удаления или изменения Firestore.

Для двух ещё не перенесённых фотографий ожидается:

```json
{
  "mode": "dry-run",
  "documentsFound": 2,
  "eligible": 2,
  "dryRunPhotos": 2,
  "errors": 0,
  "uploadedBytes": 0,
  "preflightPassed": true,
  "readyToApply": true,
  "completed": true
}
```

Если фото уже перенесено с корректным ключом этого владельца и растения,
оно учитывается как `alreadyMigrated`. Его объект не перезаписывается.
Некорректный ненулевой ключ, включая пустую строку, считается ошибкой.
Поле `photoKey: null` допускается как отсутствие ключа.

## Отдельная команда переноса

После просмотра успешного dry-run пользователь самостоятельно запускает:

```powershell
npm.cmd run migrate:remaining-photos -- --project my-plants-app-8f6fc --apply
$LASTEXITCODE
```

Этот режим не запускается автоматически. Каждый запуск заново читает Firestore:
результат прежнего dry-run не заменяет проверку актуального состояния.

Защита перед записью:

1. Сначала оба документа должны пройти проверку и локальную конвертацию.
   Если один из них не прошёл, загрузок и записей для обоих не будет.
2. Для каждого ещё не перенесённого документа проверяются владелец, base64,
   отсутствие ненулевого `photoKey`, корзины и `_photoDeleting`.
3. После конвертации документ перечитывается перед обращением к S3.
   Владелец и исходное `photo` должны совпадать с подготовленными значениями;
   остальные условия должны по-прежнему выполняться.
4. Используются существующие `convertLegacyPhoto` и `storeMigrationPhoto`:
   детерминированное имя зависит от владельца, ID растения и содержимого WebP.
   Повтор использует существующий объект только при совпадении размера, MIME и
   SHA-256 в метаданных. Ошибка HEAD или несовпадение объекта не приводят к перезаписи.
5. Транзакция Firestore повторно читает документ и проверяет те же условия,
   включая неизменность владельца и исходного фото. При повторе транзакции
   проверки выполняются заново. Записывается только `photoKey`.
6. Поле `photo` и все остальные поля сохраняются. Удалений объектов и документов нет.

UID, имена, base64, ключи объектов, секреты, подписанные URL и исходные ошибки SDK
в отчёт не попадают. Выводятся только два фиксированных ID, безопасные статусы/коды,
счётчики и размеры. Код выхода `0` означает завершение без ошибок, `1` — ошибку.

Операция не является общей транзакцией для двух растений и S3. При ошибке после
первого успешного переноса он сохраняется, а следующие загрузки прекращаются.
Повтор той же команды продолжит работу: сохранённый ключ пропускается,
загруженный объект без ключа в Firestore переиспользуется. Объект, загруженный до
конкурентного изменения документа, может остаться непривязанным; скрипт его не удаляет.
Не запускайте параллельные миграции или удаление растений/фотографий.

## Проверка после переноса

Если остальная база не изменилась:

```powershell
npm.cmd run verify:photos -- --project my-plants-app-8f6fc --expect-photo-keys 266 --expect-trash-base64 47
```

Ожидаются 266 успешно проверенных объектов, 265 пар `photo` + `photoKey`,
0 активных base64 без ключа, отсутствие ошибок и потенциальных проблем.
47 растений в корзине остаются без изменений. Старые base64 эта команда не удаляет.

## Локальные тесты

```powershell
npm.cmd run test:server
```

Адресные тесты проверяют запрет расширения охвата, получение разных владельцев,
отсутствие облачных операций в dry-run, сохранность всех полей, запрет загрузок
при ошибке предварительной проверки, изменения владельца/фото/ключа/корзины/блокировки,
повторы транзакции, сбои S3 и Firestore, потерю ответов и повтор без дублирования загрузки.
Записи в режиме apply моделируются исключительно в памяти, без `.env.local`,
серверных секретов и сети. Живой CLI с `--apply` тесты не запускают.
